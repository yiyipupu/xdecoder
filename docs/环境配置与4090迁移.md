# XDecoder 安装、单图复现与4090迁移

## 1. 已验证范围

2026-11-12，RTX3060 12GB、Ubuntu20.04、CUDA Toolkit11.8：Focal-T 在线和阻断网络单图前向均通过，输出图片逐字节一致。输入 fruit.jpg，文本 `the larger watermelon`，短边512，输出477×634，前景10625像素，峰值已分配显存1061 MiB。权重SHA256与官方一致，依赖检查通过，叠加图已查看。

**4090和训练尚未实测。** 本文先完成单卡推理，再说明训练数据准备；不需要为单图验收下载完整数据集。

源码基线：`165f8a6314ac84f5c36aaab7216f90dd97e38a43`。环境为 Python3.10、torch2.1.0+cu118、torchvision0.16.0+cu118、timm0.4.12、transformers4.34.0。Detectron2使用作者分支 detectron2-xyz，不能用SAN的版本替代。

## 2. 克隆与路径配置

```bash
git clone https://github.com/yiyipupu/xdecoder.git
cd xdecoder
export XD_ROOT="$PWD"
export XD_STORAGE="$HOME/models/xdecoder"
export CUDA_HOME=/usr/local/cuda-11.8
mkdir -p "$XD_STORAGE/weights" "$XD_STORAGE/cache" logs outputs
```

每次打开终端都应重新设置这些变量。`XD_ROOT`为代码根目录，`XD_STORAGE`为权重和缓存位置。原机器使用 `/media/pupu/PUPU/insPart/XD`，协作者可自由选择本机目录。环境和编译产物建议放本机Linux文件系统。

先检查 `nvidia-smi`、`nvcc --version`、`gcc --version`。nvidia-smi中的CUDA版本是驱动能力，不是Toolkit版本。需要CUDA11.8 Toolkit及兼容驱动；已有可用驱动时无需重装。

## 3. 创建独立环境与安装

```bash
conda create -n instructpart-xdecoder python=3.10 pip -y
conda activate instructpart-xdecoder
unset PYTHONPATH
export PATH="$CUDA_HOME/bin:$PATH"
python -m pip install 'pip<25' 'setuptools<70' wheel ninja \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip install torch==2.1.0 torchvision==0.16.0 \
  --index-url https://download.pytorch.org/whl/cu118
python -m pip install --no-build-isolation -r deployment/requirements.lock.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
```

torch大文件可用国内镜像或已下载的匹配cp310/linux_x86_64 wheel，但安装后必须确认 `torch.version.cuda` 为11.8。锁定清单排除了torch、torchvision和Detectron2，这三者需单独安装。不要直接用 `pip-freeze.raw.txt` 重建，其中保留了原机器安装路径。

系统需有C/C++编译工具及OpenMPI开发库；若缺少，可在Ubuntu安装：

```bash
sudo apt-get update
sudo apt-get install -y build-essential libopenmpi-dev openmpi-bin
```

在目标GPU可见时编译固定版本Detectron2：

```bash
MAX_JOBS=2 python -m pip install --no-build-isolation --no-deps \
  'git+https://github.com/MaureenZOU/detectron2-xyz.git@42121d75e10d9f858f3a91b6a39f5722c02868f0'
source deployment/env.sh
python -m pip check
python deployment/probe_gpu.py
python -c 'from modeling import build_model; print("XDecoder imports passed")'
```

4090需要在目标机重新编译，不能搬3060的扩展二进制。Focal-T当前推理不需要编译 `modeling/vision/encoder/ops`；提示deformable encoder不可用而模型仍能导入，不代表当前路径失败。

`mpi4py==3.1.5`需使用上面的非隔离构建，避免新版构建工具不兼容。env.sh启用protobuf的Python实现以兼容wandb；TensorBoard固定2.14.0。未安装DeepSpeed、Gradio、Whisper，当前推理不使用它们。`deployment/install.sh`保留原机安装过程和SAN wheel路径，**协作者重建请使用本节命令**。

## 4. 权重与tokenizer

```bash
curl -fL --retry 5 -C - \
  https://huggingface.co/xdecoder/X-Decoder/resolve/main/xdecoder_focalt_last.pt \
  -o "$XD_STORAGE/weights/xdecoder_focalt_last.pt"
sha256sum "$XD_STORAGE/weights/xdecoder_focalt_last.pt"
```

文件应为658330805字节，SHA256：

```text
9ddc9672a1fb8c0e463b4bc0c0e788739d08899b89c5cb901e581e3bbda6fb6d
```

也可复制原机同名文件并核对该值。模型不在Git仓库中。CLIP tokenizer文件已随 `deployment/tokenizer/` 提交，前向脚本通过本地路径加载，无需另下完整CLIP权重。国内hf-mirror在原机曾返回308错误；下载失败可换官方源，保留续传文件，不要把HTML错误页作为权重。

## 5. 单图运行、离线验收和结果

```bash
conda activate instructpart-xdecoder
cd "$XD_ROOT"
source deployment/env.sh
set -o pipefail
bash deployment/run_forward.sh 2>&1 | tee logs/forward.log
```

脚本使用当前激活环境的python；也可设置 `XD_PYTHON=/实际环境/bin/python`。输出在 `outputs/forward/`：`mask.png`、`overlay.png`、`result.json`。

自选图片或修改文本时，直接调用：

```bash
python deployment/smoke_forward.py --method xdecoder --repo "$XD_ROOT" \
  --weights "$XD_STORAGE/weights/xdecoder_focalt_last.pt" \
  --image inference/images/fruit.jpg --text 'the larger watermelon' \
  --short-side 512 --output "$XD_ROOT/outputs/custom"
```

阻断网络重复验收：

```bash
python deployment/offline_run.py deployment/smoke_forward.py \
  --method xdecoder --repo "$XD_ROOT" \
  --weights "$XD_STORAGE/weights/xdecoder_focalt_last.pt" \
  --image inference/images/fruit.jpg --text 'the larger watermelon' \
  --short-side 512 --output "$XD_ROOT/outputs/offline" \
  2>&1 | tee logs/offline.log
```

验收需确认退出码0、status为forward_passed、结果尺寸等于原图、数值有限，检查权重缺失/不匹配日志，并打开叠加图。记录GPU、torch/CUDA、输入尺寸和显存。显存不足先检查其他GPU进程，再将短边降至384或256并记录；不据此声称论文精度或训练通过。

实时查看：`tail -f logs/forward.log`。原机历史配置日志为 `logs/progress.log`，日志未上传Git；成功摘要保存在 `deployment/validation-results.json`。

## 6. 数据集准备：推理与训练分开

单图推理只需普通RGB图片和文本，仓库已含示例图；不需要mask、标注JSON、COCO或InstructPart。

训练/完整评测是后续工作。先确定训练任务和配置，再按 [官方数据说明](assets/readmes/DATASET.md)、[训练说明](assets/readmes/TRAIN.md) 准备数据。不要仅创建空目录或只下载一张图就启动官方联合训练。

官方COCO联合任务的目录示意如下，具体文件以选用的数据注册项为准：

```text
.xdecoder_data/
├── coco/
│   ├── train2017/
│   ├── val2017/
│   ├── panoptic_train2017/
│   ├── panoptic_semseg_train2017/
│   ├── panoptic_val2017/
│   ├── panoptic_semseg_val2017/
│   └── annotations/
│       ├── panoptic_val2017.json
│       ├── panoptic_train2017_filtrefgumdval_filtvlp.json
│       ├── grounding_train2017_filtrefgumdval_filtvlp.json
│       ├── captions_train2017_filtrefgumdval_filtvlp.json
│       ├── caption_class_similarity.pth
│       └── refcocog_umd_val.json
└── pretrain_arrows_code224/
    └── coco_caption_karpathy_test.arrow
```

准备顺序：

1. 获取COCO2017图像、panoptic标注；按官方说明引用的Mask2Former流程生成semantic标注，不能用panoptic RGB图直接代替semantic类别图。
2. 根据所选注册项补齐caption、grounding及过滤版本JSON。附加文件在官方说明列出的Hugging Face地址下载，放到 `coco/annotations/`；文件名必须与 `datasets/registration/` 实际引用一致。
3. 官方视觉语言分支需要Arrow数据。测试Arrow仅供调试，不等于完整训练的约4M图文数据；正式训练需准备ViLT格式数据并保留官方去重划分，避免验证集泄漏。
4. 只有启用对应任务时再准备ADE20K、RefCOCO、Cityscapes等测试数据；LVIS额外标注主要用于相应SEEM/LVIS分支。修改配置测试列表时也需同步修改相应任务开关和loader。

```bash
export DATASET=/实际路径/.xdecoder_data
export DATASET2="$DATASET"
export DETECTRON2_DATASETS="$DATASET"
export VLDATASET="$DATASET"
```

这些变量应在导入数据注册模块前设置。检查配置中的训练/测试数据名，并逐一核对 `datasets/registration/` 和mapper字段；不要假定所有注册项读取同一变量。caption评测的Java/coco-caption资源按官方说明额外配置，单图前向不需要。

当前未验证训练入口或数据加载。官方多卡命令不能直接视为单卡4090配置：应先以小batch验证数据加载、有限loss、反向、参数更新、checkpoint保存/恢复，再确定学习率和训练周期。自建2–4张图片可做训练流程调试，但需编写匹配的注册和mapper，不是现成训练入口。

## 7. 迁移交付清单

复制/克隆本仓库，复制权重并核对SHA256；设置本机路径，创建独立Conda环境并在目标GPU编译Detectron2。按顺序执行pip check、GPU探针、导入检查、单图前向、离线前向并保存结果。仅完成这些检查后标记4090推理通过；训练需另行验收。
